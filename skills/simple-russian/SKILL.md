# Simple Russian — информационный стиль для технических текстов

Скилл задаёт правила простого русского технического языка. Основа: ASD-STE100
(Simplified Technical English), информационный стиль (Максим Ильяхов),
принципы ясной прозы (Нора Галь).

Цель текста — действие читателя, а не впечатление. Каждое предложение либо
сообщает факт, либо даёт команду. Всё остальное — удалить.

## Карта директив

Директивы D1–D11 общие с `simple-english`. Один номер означает одно правило
в обоих языках. Различаются только примеры и пометки об особенностях языка.
Директивы R1–R5 учитывают особенности русского языка, в английском их нет.

| ID | Правило | Область |
|---|---|---|
| D1 | Повелительное наклонение в инструкциях | Общая |
| D2 | Действительный залог | Общая |
| D3 | Глагол вместо отглагольного существительного | Общая |
| D4 | Одно действие — одно предложение | Общая |
| D5 | Явные условия — в начале | Общая |
| D6 | Без воды и стоп-слов | Общая |
| D7 | Один термин — одно понятие | Общая |
| D8 | Факты и точные значения | Общая |
| D9 | Предупреждение до инструкции | Общая |
| D10 | Списки и таблицы | Общая |
| D11 | Сообщение об ошибке: что, почему, что делать | Общая |
| R1 | Без канцелярита | Только RU |
| R2 | Цепочки родительного падежа ≤ 2 | Только RU |
| R3 | Прямой порядок слов | Только RU |
| R4 | Без деепричастных оборотов в инструкциях | Только RU |
| R5 | Вид глагола и форма команды | Только RU |

## Когда применять

- Инструкции, runbook'и, README, onboarding-документы на русском.
- Тексты интерфейса: кнопки, подсказки, сообщения об ошибках.
- Ответы поддержки, release notes, внутренние регламенты.
- Редактура чужого текста: переписать по директивам D1–D11 и R1–R5, затем прогнать чек-лист.

## Приоритет правил

1. Точность. Не удаляйте нужную техническую информацию ради краткости.
2. Ясность. Одно предложение — одна мысль. Одно слово — одно значение.
3. Краткость. Удаляйте слова, которые не несут информации.

Если правило ниже мешает точности, сохраните факт и перестройте предложение.

## Жёсткие ограничения (hard limits)

| Параметр | Лимит | Директива |
|---|---|---|
| Предложение-инструкция | ≤ 15 слов | D4 |
| Описательное предложение | ≤ 20 слов | — |
| Абзац | ≤ 6 предложений | — |
| Мыслей в предложении | 1 | — |
| Действий в предложении-инструкции | 1 | D4 |
| Условий в предложении | 1 | D5 |
| Уровней вложенности списка | ≤ 2 | D10 |
| Цепочка родительных падежей | ≤ 2 слов подряд | R2 |

Лимиты не «рекомендации». Нарушение лимита — дефект текста, как падающий тест.

Лимит слов ниже, чем в английском (15 против 20): в русском нет артиклей,
а падежи заменяют предлоги. Та же мысль занимает меньше слов.

## Общие директивы D1–D11

### D1. Повелительное наклонение в инструкциях

Инструкция — команда, а не пожелание. «Рекомендуется», «следует», «необходимо» —
читатель не понимает, обязан он или нет.

| Плохо | Хорошо |
|---|---|
| Сервис должен быть запущен. | Запустите сервис. |
| Рекомендуется создать резервную копию. | Создайте резервную копию. |
| Необходимо убедиться в наличии доступа. | Проверьте доступ. |
| Пользователю следует ввести токен. | Введите токен. |

Если действие действительно опционально — скажите это явно:
«Необязательно: включите кэш, чтобы ускорить сборку».

Вид глагола и единая форма команды — см. R5.

### D2. Действительный залог вместо страдательного

Страдательный залог скрывает деятеля. Читатель не знает, кто действует: он,
система или скрипт.

| Плохо | Хорошо |
|---|---|
| Данные удаляются скриптом. | Скрипт удаляет данные. |
| Файл должен быть создан пользователем. | Создайте файл. |
| Ошибка была зафиксирована системой мониторинга. | Мониторинг зафиксировал ошибку. |
| Настройки будут применены после перезапуска. | Сервис применит настройки после перезапуска. |

Особенность русского: глагол на «-ся» в значении пассива («файл удаляется»,
«настройки применяются») — тоже страдательный залог. Назовите деятеля.

Исключение: деятель неизвестен или не важен, и фраза короче активной формы.
Такое исключение допустимо только в описании и не чаще одного раза на абзац.
В инструкциях — никогда.

### D3. Глагол действия вместо отглагольного существительного

Отглагольное существительное прячет действие и требует глагола-пустышки.
Такая пара называется расщеплённым сказуемым.

| Плохо | Хорошо |
|---|---|
| Произведите проверку конфигурации. | Проверьте конфигурацию. |
| Выполните перезагрузку сервера. | Перезагрузите сервер. |
| Осуществляется отправка отчёта. | Скрипт отправляет отчёт. |
| Обеспечьте сохранение изменений. | Сохраните изменения. |
| осуществлять запуск | запускать |
| производить мониторинг | следить |

Маркеры для поиска: «произвести», «осуществить», «выполнить + существительное»,
«обеспечить», слова на «-ание/-ение» рядом с пустым глаголом.

### D4. Одно действие — одно предложение

Читатель выполняет инструкцию по шагам. Два действия в предложении —
одно из них он пропустит.

| Плохо | Хорошо |
|---|---|
| Остановите сервис, очистите кэш и перезапустите сервер. | 1. Остановите сервис. 2. Очистите кэш. 3. Перезапустите сервер. |
| Откройте настройки и включите двухфакторную аутентификацию. | 1. Откройте настройки. 2. Включите двухфакторную аутентификацию. |

Исключение: два действия физически неразделимы
(«Нажмите и удерживайте кнопку 3 секунды»).

Особенность русского: второе действие часто прячется в деепричастный оборот
(«…, предварительно сохранив логи»). См. R4.

### D5. Явные условия, условие — в начале

Схема: «Если X, сделайте Y». Условие после действия читатель замечает, когда
действие уже выполнено. Одно условие — одно предложение.

| Плохо | Хорошо |
|---|---|
| Перезапустите сервис в случае обнаружения ошибки в логах. | Если в логах есть ошибка, перезапустите сервис. |
| Данные будут потеряны при отсутствии резервной копии. | Если резервной копии нет, вы потеряете данные. |
| Запустите миграцию, но только на staging. | Только на staging: запустите миграцию. |

Не используйте размытые условия: «при необходимости», «по возможности»,
«где применимо», «в большинстве случаев». Назовите точное условие или удалите его.

Особенность русского: условие часто прячут в отглагольный оборот
(«при наличии», «в случае возникновения», «при отсутствии»). Замените на
«если» + глагол. Это одновременно нарушение R1.

### D6. Удалить воду и стоп-слова

Слова, которые можно удалить без потери смысла, — удалить.

Чёрный список (неполный): «как известно», «следует отметить», «стоит заметить»,
«в настоящее время», «на сегодняшний день», «является одним из», «в конечном
итоге», «по сути», «собственно», «достаточно», «довольно», «просто», «некий»,
«определённый», «соответствующий», «данный», «вышеуказанный».

| Плохо | Хорошо |
|---|---|
| Следует отметить, что в настоящее время сервис является одним из ключевых компонентов системы. | Сервис — ключевой компонент системы. |
| Просто откройте соответствующий файл конфигурации. | Откройте файл `config.yml`. |
| В конечном итоге данный подход позволяет добиться повышения производительности. | Подход ускоряет систему на 30%. |

Проверка: удалите слово. Смысл не изменился — слово было лишним.

### D7. Один термин — одно понятие

Выберите один термин для каждого понятия и держите его во всём документе.
Синонимы ради разнообразия запрещены.

| Понятие | Используйте | Не используйте |
|---|---|---|
| начать действие | запустить | стартовать, инициировать, осуществить запуск |
| проверить | проверить | верифицировать, проинспектировать, осуществить проверку |
| удалить | удалить | ликвидировать, зачистить, устранить |
| использовать | использовать | задействовать, утилизировать (калька с «utilize») |
| показать | показать | отобразить, продемонстрировать |
| убедиться | убедиться | удостовериться, обеспечить уверенность |

Особенности русского:
- Школьное правило «не повторяйтесь» в техническом тексте не действует.
  Повтор термина — норма. Синоним заставляет читателя гадать, то же ли это понятие.
- Английский термин или русский перевод: выберите одну форму на документ.
  «Деплой» или «развёртывание» — не оба сразу.
- Не создавайте гибриды из английского корня и русского суффикса
  («резильентность», «ремедиация»). Используйте русское слово или английский
  термин как есть.

Расшифруйте аббревиатуру при первом упоминании: «система управления базами
данных (СУБД)». Исключение: общеизвестные в контексте (API, URL, HTTP, ID).

Исключение: официальное название API, команды или продукта сохраните как есть.

### D8. Факты и точные значения

Замените оценочное прилагательное измерением или удалите его.

| Плохо | Хорошо |
|---|---|
| очень быстро | p95 = 40 мс |
| значительно улучшен | задержка −35% |
| большой файл | файл больше 2 ГБ |
| надёжное решение | 0 сбоев на 10 000 запусков |

- Если метрики нет, сообщите факт без прилагательного.
- Ссылка на код — `путь/файл.ext:строка`. Ссылка на раздел — точный заголовок.

Особенности русской типографики:
- Число и единицу разделяйте пробелом: «200 мс», «4 ГБ». В вёрстке — неразрывным пробелом.
- Десятичный разделитель в тексте — запятая: «2,5 ГБ». В коде, командах
  и конфигах копируйте значение из источника как есть (обычно с точкой).
- Разряды отделяйте пробелом в числах от 10 000: «10 000», но «1000».

### D9. Предупреждение ДО инструкции

Читатель выполняет шаги по порядку. Предупреждение после команды приходит
слишком поздно.

Плохо:

> Выполните `DROP TABLE sessions;`. Внимание: команда необратимо удаляет данные.

Хорошо:

> **Осторожно:** команда необратимо удаляет все сессии. Сначала сделайте резервную копию.
>
> Выполните `DROP TABLE sessions;`.

Градация (одинаковая во всех трёх скиллах):
- **Осторожно** (EN `Warning`) — риск травмы, потери данных, денег, доступа или нарушения безопасности.
- **Внимание** (EN `Caution`) — риск сбоя, простоя, деградации или лишней работы.
- **Примечание** (EN `Note`) — полезный контекст без риска.

Не помещайте риск в «Примечание».

### D10. Списки и таблицы вместо полотен текста

| Содержимое | Формат |
|---|---|
| 3 и больше шагов | Нумерованный список |
| 3 и больше элементов с деталями (параметр с типом, условие с действием) | Маркированный список |
| Элементы с 2+ атрибутами каждый (тип, обязательность, значение по умолчанию) | Таблица |
| До 3 коротких элементов без деталей (1–3 слова) | Можно в строку: «JSON, YAML и TOML» |
| 4 и больше коротких элементов | Маркированный список |

- Нумерованный список — только когда порядок важен. Иначе — маркированный.
- Вложенность списков — не больше 2 уровней. Нужно больше — таблица или отдельный раздел.

Плохо:

> Скрипт принимает несколько параметров: во-первых, путь к конфигурации,
> который обязателен, во-вторых, флаг подробного вывода, который необязателен,
> и наконец таймаут в секундах, по умолчанию равный тридцати.

Хорошо:

> Параметры скрипта:
>
> | Параметр | Обязательный | По умолчанию |
> |---|---|---|
> | `--config` — путь к конфигурации | да | — |
> | `--verbose` — подробный вывод | нет | выключен |
> | `--timeout` — таймаут, секунды | нет | 30 |

### D11. Сообщение об ошибке: что случилось → почему → что сделать

Каждая часть — одно короткое предложение. Кнопка называет действие (форма — см. R5).

| Плохо | Хорошо |
|---|---|
| Произошла ошибка. | Не удалось сохранить файл: диск заполнен. Удалите старые файлы и повторите. |
| Что-то пошло не так. Попробуйте позже. | Оплата не прошла: банк не ответил за 30 с. Повторите оплату. |

## Директивы только для русского R1–R5

Эти правила учитывают грамматику русского языка. У `simple-english` свои
языковые директивы (E1–E3).

### R1. Без канцелярита

Канцелярит — штампы, которые удлиняют текст и не добавляют смысла.
Расщеплённые сказуемые («осуществлять запуск») — частный случай, см. D3.

| Плохо | Хорошо |
|---|---|
| в целях реализации данного функционала | чтобы это работало |
| на предмет наличия ошибок | нет ли ошибок |
| в случае возникновения проблем | если что-то сломалось |
| в рамках данного процесса | в этом процессе |
| Ускорьте сборку путём внесения изменений в конфиг. | Измените конфиг. Сборка ускорится. |
| имеет место задержка | есть задержка |

Правило замены: штамп → одно слово или короткий оборот. Если после замены
смысл не изменился — штамп был мусором.

### R2. Разорвать цепочки родительного падежа

Больше двух родительных подряд — читатель теряет связи между словами.
В английском та же проблема выглядит как цепочка существительных (E1 в `simple-english`).

| Плохо | Хорошо |
|---|---|
| проверка конфигурации сервера баз данных пользователей | проверьте, как настроен сервер с пользовательскими базами данных |
| журнал ошибок процесса обработки очереди сообщений | журнал ошибок обработчика очереди |
| план оптимизации скорости загрузки страниц сайта | план: ускорить загрузку страниц сайта |

Приёмы разрыва: глагол вместо существительного (D3), прилагательное
(«базы данных пользователей» → «пользовательские базы»), предлог
(«обработки очереди» → «для очереди»), разбивка на два предложения.

### R3. Прямой порядок слов

Подлежащее → сказуемое → дополнение. В русском порядок слов свободный,
поэтому инверсия грамматически допустима. В инструкции она замедляет чтение.

| Плохо | Хорошо |
|---|---|
| Скриптом при каждом запуске создаётся временный файл. | Скрипт при каждом запуске создаёт временный файл. |
| Для корректной работы сервиса требуется настроенный DNS. | Сервису нужен настроенный DNS. |
| Важным условием стабильности является мониторинг. | Мониторинг обеспечивает стабильность. |

Обстоятельство времени или условия может стоять в начале (см. D5) —
это не нарушение.

### R4. Без деепричастных оборотов в инструкциях

Деепричастный оборот прячет второе действие и его порядок. Читатель не
понимает, что делать сначала.

| Плохо | Хорошо |
|---|---|
| Открыв файл, проверьте строку 12. | 1. Откройте файл. 2. Проверьте строку 12. |
| Перезапустите сервер, предварительно сохранив логи. | 1. Сохраните логи. 2. Перезапустите сервер. |
| Нажмите «Сохранить», убедившись, что поля заполнены. | 1. Проверьте, что поля заполнены. 2. Нажмите «Сохранить». |

Длинный причастный оборот замените придаточным с «который»:

| Плохо | Хорошо |
|---|---|
| Падает сервис, обрабатывающий входящие запросы от внешних партнёров по API. | Падает сервис, который обрабатывает запросы партнёров по API. |

Короткое причастие из одного-двух слов допустимо: «настроенный DNS».

### R5. Вид глагола и форма команды

- В разовой команде — совершенный вид: «Откройте файл», не «Открывайте файл».
- Несовершенный вид — для повторяющихся действий и запретов:
  «Проверяйте логи каждый день», «Не открывайте файл во время сборки».
- Одна форма команды на документ: повелительное наклонение на «вы»
  («Откройте»). Не смешивайте с инфинитивом («Открыть файл») и с «ты» («Открой»).
- Кнопки и пункты меню — инфинитив: «Сохранить», «Повторить». Устоявшиеся
  подписи вроде «Отмена» и «ОК» сохраните. Выберите одну норму и держите её
  во всём интерфейсе.

## Полные примеры преобразования

### Пример 1. IT-процедура

До:

> В целях обеспечения корректного функционирования системы необходимо
> осуществить проверку статуса сервиса аутентификации пользователей портала
> на предмет наличия ошибок. В случае обнаружения ошибок рекомендуется
> произвести перезапуск сервиса, при этом следует отметить, что перед
> перезапуском должно быть выполнено сохранение текущих логов, так как
> в противном случае данные логов будут утеряны, что может затруднить
> последующий анализ причин возникновения проблемы.

После:

> **Осторожно:** перезапуск стирает текущие логи. Сначала сохраните их.
>
> 1. Проверьте статус сервиса аутентификации: `systemctl status auth-service`.
> 2. Если ошибок нет, закройте задачу.
> 3. Если есть ошибки, сохраните логи: `journalctl -u auth-service > auth.log`.
> 4. Перезапустите сервис: `systemctl restart auth-service`.
> 5. Повторите шаг 1.

### Пример 2. Техническое описание

До:

> Данный модуль является одним из ключевых компонентов подсистемы обработки
> очереди входящих сообщений пользователей и осуществляет выполнение
> валидации получаемых данных, после чего производится их сохранение
> в базу данных, при этом в настоящее время обеспечивается поддержка
> двух форматов сообщений.

После:

> Модуль обрабатывает входящие сообщения пользователей. Он валидирует данные
> и сохраняет их в базу.
>
> Поддерживаемые форматы: JSON и Protobuf.

### Пример 3. Сообщение об ошибке / текст интерфейса

До:

> Произошла ошибка при осуществлении попытки сохранения внесённых вами
> изменений в связи с отсутствием соединения с сервером. Рекомендуется
> произвести проверку подключения к сети интернет и повторить попытку позже.

После:

> Не удалось сохранить изменения: нет соединения с сервером.
>
> Проверьте интернет и нажмите «Повторить».
>
> [Повторить] [Отмена]

Сообщение построено по D11, подписи кнопок — по R5.

## Чек-лист ревью

Прогоните текст по пунктам. Любой «нет» — вернуть на доработку.

Лимиты:
- [ ] Инструкции ≤ 15 слов, описания ≤ 20 слов, абзацы ≤ 6 предложений.

Общие директивы:
- [ ] D1: инструкции в повелительном наклонении, нет «рекомендуется/следует/должен быть». Необязательные шаги помечены «Необязательно:».
- [ ] D2: нет страдательного залога (в том числе «-ся» в значении пассива) без явного оправдания.
- [ ] D3: нет «произвести/осуществить/выполнить + существительное».
- [ ] D4: одно действие на предложение-инструкцию.
- [ ] D5: условия в форме «Если X, сделайте Y», условие в начале, одно на предложение, без «при необходимости».
- [ ] D6: нет стоп-слов («данный», «является», «в настоящее время», «просто», «соответствующий»).
- [ ] D7: один термин на понятие, нет гибридов, аббревиатуры расшифрованы.
- [ ] D8: оценки заменены числами. Единицы, десятичная запятая и разряды оформлены.
- [ ] D9: предупреждения стоят до опасных шагов, уровень соответствует шкале.
- [ ] D10: списки и таблицы по порогам D10, вложенность ≤ 2.
- [ ] D11: сообщение об ошибке: что случилось, почему, что сделать.

Директивы только для русского:
- [ ] R1: нет канцелярита («в целях», «на предмет», «в рамках», «имеет место»).
- [ ] R2: цепочки родительных разорваны.
- [ ] R3: прямой порядок слов: подлежащее → сказуемое → дополнение.
- [ ] R4: нет деепричастных оборотов в инструкциях. Длинные причастные обороты заменены на «который».
- [ ] R5: совершенный вид в разовых командах. Одна форма команды на документ.

Финальная проверка:
- [ ] Каждое предложение сообщает факт или даёт команду.
- [ ] Удаление любого слова меняет смысл. Если нет — слово лишнее.
- [ ] Ничего технически нужного не удалено ради краткости.
- [ ] Читатель после текста знает, что делать, без повторного чтения.

## Применение

- При написании: применяйте директивы во время генерации, а не после.
- При ревью: процитируйте каждое нарушение, назовите директиву (D1–D11, R1–R5)
  и дайте пару «плохо / хорошо».
- При переписывании: сохраните все факты. Если исходник неясен, запишите
  неясность как открытый вопрос. Не выдумывайте точное значение.
- Двуязычная работа (RU + EN) или перевод: загрузите также `simple-lang`.
  Он загрузит `simple-english` и добавит правила паритета версий.
